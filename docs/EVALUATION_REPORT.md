# ScholarPilot 로컬 평가 보고서

## 범위와 한계

실제 교과서의 검색은 두 PDF와 인덱스를 읽기만 하여 평가했다. 관련성은 질문별 수동 지정 용어군이 청크 본문 또는 절 제목에 등장하는지에 대한 **대리 지표**다. 인간의 정답 레이블, 의미 이해도, 학습 효과 또는 AI 설명 품질을 측정하지 않는다. PDF 원문은 결과 파일에 저장하지 않았다.

검색 전후는 동일한 12개 질문·동일한 인덱스·동일한 평가 코드다. 측정은 각각 1회이며 캐시와 부하가 다르므로 검색 시간의 변화는 성능 향상으로 단정할 수 없다.

## Baseline RAG와 Agentic Learning: 오프라인 제어 흐름

같은 12개 질문과 두 자체 제작 PDF를 사용했다. Agent의 추가 질문·오답 제출·중복 제출은 자동으로 이어졌으며 Baseline은 첫 응답만 처리했다. 시간은 서로 다른 단계 수를 포함하므로 모델 또는 학습 효과의 비교가 아니다.

Agent의 검색·선수 개념·퀴즈·평가·복습 도구 실행과 저장만 확인한 결과다. 실제 모델의 개념 진단·설명·채점 품질이나 학습자의 성취 향상은 아직 평가하지 않았다. 동일 데이터로 추후 실제 API 비교를 하려면 명시적 유료 호출 승인과 호출 상한이 필요하다.

인덱싱 시간은 각 1회이며 디스크 캐시·부하에 영향을 받는다. 재인덱싱 전후의 트랜잭션 방식 변경은 반복적인 FTS 삭제 조회를 줄인다. 읽기 동시성 시험과 테스트용 동시 퀴즈 제출 시험을 수행했으며 장시간 부하 시험은 아니다.

Windows WinError 10014가 테스트 서버 초기화에서 재현됐다. 원인은 확인되지 않았고 동일 오류에만 횟수 제한 재시도를 적용했다. 다른 에러에는 재시도하지 않는다.

## 재현

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_retrieval.py --output docs/retrieval-after.json
.\.venv\Scripts\python.exe scripts/evaluate.py
.\.venv\Scripts\python.exe scripts/benchmark_local.py
.\.venv\Scripts\python.exe scripts/port_conflict_probe.py
.\.venv\Scripts\python.exe scripts/render_evaluation_report.py
```

검색 평가는 사용자 책을 읽기만 한다. Agent와 인덱싱 성능 평가는 새 `data/evaluation-runs/`, `data/benchmarks/` 격리 저장소에 생성되며 사용자 기록을 변경하지 않는다. 실행마다 새 저장소가 생긴다.

추후 같은 질문과 자체 제작 PDF로 유료 실제 모델을 평가하려면 `.env` 설정 후 사용자가 명시적으로 `scripts/evaluate.py --mode live --approve-paid-api --max-total-api-calls N`을 실행한다. 호출 상한을 지정해도 실제 비용과 품질은 모델 및 계정 조건에 따라 달라진다. 이번 평가에서는 실행하지 않았다.

## 2026-11-17 Bayes 실제 모델 평가 준비

기존 평가 JSON의 한국어 질문과 일부 문서가 물음표로 손상돼 있었다. UTF-8로 복구한 후 재실행한 실제 PDF 24개 사례의 근거 확인은 24/24, 지정 페이지 상위 8개 적중은 13/24, 반환 청크 원문 일치는 136/136이다. 이전 손상된 질문으로 얻은 12/24 수치는 폐기한다. 단일 지정 페이지의 엄격한 적중률이며 의미 관련성 또는 실제 설명 품질 점수가 아니다.

새 Bayes 평가 실행기는 실제 Bishop PDF와 기존 L01 사례를 사용하고, 사용자 학습 이력이 없는 격리 DB에서 수행한다. 오프라인 11회 모델 대역 응답으로 설명·선수 지식·문제 대기·오답 채점·이해도 갱신·복습 추천을 검증했다. 출처 텍스트와 PDF 페이지 일치, 초기 인용 존재, 미해결 인용 없음도 확인했다. 결과는 `bayes-offline-readiness.json`, 상세 응답과 입력은 그 파일이 가리키는 로컬 `data/` 경로에 있다.

최종 백엔드 전체 58개, 프런트엔드 2개, TypeScript 검사와 프로덕션 빌드 통과. 실제 PDF 브라우저 기존 모델 대역 4개, Mock 2개, 새 Bayes 시나리오 1개 통과. SDK MockTransport로 실제 설치 SDK의 요청 직렬화와 응답 파싱을 확인했으며 네트워크를 사용하지 않았다. 별도 인코딩 테스트 결과는 아래 추가 검증 기록을 참조한다.

모든 실행은 유료 API 호출 0회다. 실제 모델 평가 점수는 null이며 수식 유도와 의미 관련성, 학습 효과는 미검증이다. [승인 전 조건](BAYES_LIVE_PREFLIGHT.md), [평가 기준](LEARNING_EVALUATION.md)을 참조한다.

추가 검증: 인코딩 복구 회귀 테스트를 포함한 관련 12개 테스트가 통과했다. 전체 58개 실행 후 새 인코딩 테스트 1개를 추가 확인하여 검증된 백엔드 테스트는 총 59개다. 호출 로그와 예산 차단, API 키 보호, 실제 SDK 오프라인 계약 테스트를 포함한다.
