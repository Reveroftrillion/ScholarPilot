## 시나리오별 결과

- A: 실제 브라우저에서 Bishop PDF 48페이지(인쇄 28페이지)를 열고 지정 질문을 전송했다. `get_current_page`가 실행됐고 전달 문맥의 16개 청크가 원본 PDF와 일치했다. 첫 모델 요청이 거절돼 한국어 설명, 생성 수식, 계산 예제, 모델 인용과 인용 클릭은 미검증이다.
- B: 추가 비용을 발생시키지 않기 위해 실제 모델 진단·채점·오답 설명·학습 추천을 실행하지 않았다. 실제 학습 기록의 생성·복원 성공으로 보고하지 않는다.
- C: 실제 모델 호출 미실행. 로컬 원문 감사에서 Machine Learning Systems PDF 534–545페이지 등에 PTQ/QAT 표현이 있음을 확인했다. Bishop 인덱스에서는 PTQ/QAT 및 전체 용어의 해당 정규식 일치가 없었다. 이 사실은 다른 표현까지 완전히 없다는 증거가 아니며, 두 책의 관련성을 억지로 연결하는 근거로 쓰지 않는다.

실제 모델이 생성한 설명 품질 점수와 수식·계산 검증 결과는 null이다. 실제 모델 선택 도구는 실행되지 않았고, 서버가 문맥 준비를 위해 실행한 도구는 `get_current_page`뿐이다.

## 발견한 문제와 수정

1. API 설정/계정: 크레딧 소진. 키 값을 출력하지 않고 HTTP 상태와 허용된 오류 코드만 기록한다. 계정의 크레딧 변경은 사용자 작업이다.
2. API 오류 표시: 기존 평가 실행기는 원인을 일반 실패 문구로 감췄다. 크레딧 부족·인증·모델 권한·요청 제한을 안전한 한국어 오류로 분류하도록 수정했다. SDK 원시 예외와 헤더는 남기지 않는다.
3. 예산 관리: 세 시나리오와 연결 확인 경로가 하나의 잠금·카운터·예산을 공유하는 실제 검증 서버를 추가했다. 요청 전에도 기록을 저장하며, 재시작 시 실패·미완료 요청과 예약액을 복원한다. 자동 재시도와 자동 모델 대체는 없다.
4. 기록: 실패 요청의 토큰과 비용은 알 수 없음을 명시한다. 호출/시나리오별 결과와 원본 출처 검사를 집계하는 읽기 전용 보고 스크립트를 추가했다.
5. 실행 환경: 서버 재시작 시 Windows WinError 10014가 한 번 발생했다. API 호출 없이 서버 시작만 다시 수행해 실행됐다. 운영체제 소켓 오류의 근본 원인이 해결됐다고 주장하지 않는다.
