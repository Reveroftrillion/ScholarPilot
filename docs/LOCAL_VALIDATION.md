# 실제 Ollama 학습 검증 · 2026-11-19

## 최신 단계: 설명과 검증의 책임 분리

현재 모델은 **qwen3:1.7b Q4_K_M, CPU** 그대로입니다. 모델·서비스를 추가 다운로드하지 않았고 외부 유료 호출은 0회입니다. 이번 단계는 잘못된 AI 설명을 자동 인증하지 않는 구조를 만들었습니다. **정확한 대학원 수준 설명 생성 문제 자체는 해결하지 못했습니다.** 아래 이전 단계 기록보다 이 절이 우선합니다.

### 실제 변경한 구조와 오류 수정

- `backend/reliable_flow.py`: 현재 페이지·선택문·검색 결과를 서버가 확인하고 최대 3개 짧은 발췌(합계 1,400자)를 준비합니다. 기본 설명은 1회, 심화만 선수 개념·문제를 진행합니다. 수식 확인만 필요한 요청은 모델 0회입니다. 미검증 AI 답변은 후속 질문의 정답 근거로 재사용하지 않습니다.
- `backend/math_verification.py`: 문자열 eval 없이 제한된 AST를 SymPy 객체로 변환합니다. 숫자 연산·유리식 항등식만 지원하며 변수·지수·식 크기를 제한합니다. 분모 조건을 보존합니다. 함수·적분·일반 유도·확률 가정·PDF 일치를 인증하지 않습니다. 사용자 입력 수식과 계산 검산은 별개의 정보입니다.
- `backend/pdf_math.py`, `backend/main.py`, `frontend/src/MathReview.tsx`: PDF 추출 후보를 미확정으로 표시하고 실제 PDF 영역 이미지를 제공합니다. 사용자가 수식·계산식·변수 값을 수정하고 원문을 확인할 수 있습니다. 원문 확인 체크는 사람의 확인이며 자동 증명이 아닙니다.
- `backend/quiz_validation.py`, `backend/learning.py`: 모델이 주장한 정답/신뢰도를 서버 인증으로 취급하던 위험을 제거했습니다. 독립 계산으로 검증한 수치 정답·확정된 객관식·제한된 원문 용어 동의어만 결정적으로 채점합니다. 원문 빈칸 문제는 용어 회상일 뿐 개념 이해 진단이 아닙니다. 의미 판단이 필요한 답안은 모델 의견과 불확실성을 표시하며 이해도를 확정하지 않습니다.
- `backend/database.py`: 수동 확인은 `attempt_reviews`에 추가하고 기존 답안을 덮어쓰지 않습니다. 연습 세 번 정답을 `이해 완료`로 표시하던 위험을 막고 `연습 완료`로 구분했습니다. 기존 데이터베이스에는 추가 테이블만 도입합니다.
- `backend/agent.py`: 수식 위험 답변은 별도 미검증 초안으로 분리합니다. AI 개념 설명은 수식 검산 통과 여부와 무관하게 미검증으로 표시합니다. 서버 검산 답변만 별도 출처를 갖습니다. 제출 전 정답뿐 아니라 검산 결과의 exact/value/latex도 숨깁니다.
- `backend/jobs.py`, `frontend/src/api.ts`, `main.tsx`, `RunDiagnostics.tsx`: 검색·생성·확인·오류의 실제 상태를 조회합니다. 동시 생성은 거절하며 보이지 않는 추론 대기열을 만들지 않습니다. 모델 행동과 Python 분기를 로그에 구분합니다.
- `backend/ollama_provider.py`, `backend/local_flow.py`: 신뢰 경계 경로는 문맥 상한 4,096·출력 상한 480토큰, 10분 keep-alive를 사용합니다. 기존 어댑터·Mock 호환 경로는 유지합니다.
- `backend/retrieval.py`: 한영 용어·설명형 질의 확장을 보완했습니다. 기존 FTS5를 유지하며 임베딩은 추가하지 않았습니다.

SymPy 문자열 파서는 eval을 사용할 수 있으므로 사용하지 않았습니다. [공식 파싱 문서](https://docs.sympy.org/latest/modules/parsing.html)를 참고할 수 있습니다. 지원 범위 밖의 주장은 검증 성공으로 표시하지 않습니다. 베이즈 정답을 고정한 검증기가 아니라 사용자가 입력한 일반 계산식을 독립 평가합니다.

### 검색·속도·메모리

동일 24사례의 지정 근거 페이지 적중은 **16/24→18/24**(L06·L08 개선), 근거 앵커 24/24, 반환 원문·책·페이지 192/192, 검색 범위 검사 통과입니다. 실제 모델 응답에 사용된 인용도 별도 확인해 16/16 일치했습니다. 남은 여섯 실패는 한국어 의미 확장·지정 페이지와 다른 유효 페이지 등의 문제로 남아 있으며 전면 해결로 보고하지 않습니다.

검색 시간 중앙값은 이전 88.475ms·이후 43.640ms이나 캐시·부하가 다른 단일 측정이므로 인과적인 속도 개선으로 단정하지 않습니다. 이전 A 91.752초·B 437.031초·채점 86.462초·C 120.729초와 비교해 이번 시간이 줄었지만, 설명 길이·수식 역할·문제 유형을 줄인 측정입니다. **동일 품질의 가속이나 학습 효과 향상을 입증하지 않았습니다.**

요청 전후 표본 기준 Ollama RSS 합계 최대 약 **1.39GiB**, 모델 할당 최대 **1.51GiB**, 가용 RAM 최소 **0.378GiB**, VRAM 0입니다. 실행 중 순간 피크가 아니며 브라우저·QA 서버 등 다른 프로그램의 영향을 받습니다. i5-1240P·약 8GB RAM의 CPU 환경에서 여전히 수십 초가 필요합니다. 모델 로드 시간은 `local-model-calls.json`의 요청별 load_duration에 기록하며 warm/cold를 동일 조건으로 비교하지 않았습니다. 큰 모델 설치는 진행하지 않았습니다.

## 판정과 실행 범위

이번 검증은 실제 `qwen3:1.7b` Q4_K_M, CPU, Ollama JSON 행동 프로토콜로 실행했습니다. Mock·오프라인 대역은 회귀 테스트에만 사용했고 외부 유료 AI 호출은 0회입니다. 테스트 수와 출처 ID 유효성을 설명 품질 점수로 바꾸지 않습니다.

**현재 모델로 대학원 교과서 학습 흐름 전체를 신뢰할 수 있다고 판정하지 않습니다.** 한국어 생성·검색·선택문 전달·문제·채점 저장은 실행되지만 수식 오류, 근거 없는 책 언급, 낮은 의미 채점 신뢰도가 실제로 발견됐습니다. 서버 경로는 보완했으며 남은 모델 품질 실패도 보존했습니다.

원본 서재·학습 기록을 쓰지 않고 두 PDF와 인덱스를 복사한 `data/local-evaluation-runs/c2363794b7ee4e79ae80846d70026d85/`에서 실행했습니다. 과거 실패 응답, 수정 전후 응답, 모델 호출 원장, 테스트 XML, 브라우저 오류·화면을 보존합니다. 이 디렉터리에는 교과서 원문이 있으므로 Git 제외 대상입니다.

| D: 이전 질문의 사전·사후확률 후속 설명 | 같은 B 세션의 이전 질문·답변·선택문을 문맥으로 전달 | 대화 주제는 유지하지만 이전의 잘못된 표본 수 수식을 반복하여 부분 성공 |

예를 들어 모델이 제시한 결합확률 0.2와 조건 사건의 확률 0.4에서 조건부확률은 `0.2 / 0.4 = 0.5`여야 합니다. 모델의 `0.2 * 0.5 / 0.4 = 0.25`는 산술 자체가 맞아도 결합확률을 우도로 잘못 사용했습니다. 독립 검사는 이 차이를 검출합니다. 이는 평가자가 만든 모델 답변 대체물이 아니라 실제 실패를 검산한 것입니다.

최종 A도 같은 유형입니다. 제시된 결합확률 0.2와 조건 사건 확률 0.5에서 정답은 0.4지만 모델은 0.12를 제시했습니다. 서버는 이를 검토 필요로 처리했습니다. 선택·B·D의 일부 응답은 당시 자동 검사를 통과했어도 수동 검토에서는 오류가 확인됐습니다. 해당 원본 기록의 상태를 소급해서 성공·실패로 조작하지 않습니다.

## 원인과 보완

## 남은 핵심 문제

1. 1.7B 모델의 수식·계수·의미 채점·교과서 간 주장 정확성은 부족합니다. 모델 크기를 늘리지 않고 안정적인 대학원 수학 튜터로 완성했다고 표시하지 않습니다.
2. 현재 기계의 수십 초~수분 응답은 대화형 학습에 느립니다. 측정한 메모리는 요청 전후 표본이며 실행 중 최고치가 아닙니다.
3. 자동 검사는 일반 증명 검증기나 문장별 원문 근거 판정기가 아닙니다. 실제 학습 이해도 향상 실험도 하지 않았습니다.
4. Windows 소켓 오류 10014가 테스트 서버 시작에서도 재현됐습니다. 종료된 소유 프로세스의 시작만 제한 재시도했으며 다른 포트 소유자·운영체제 네트워크를 변경하지 않았습니다.

다음 단계는 실패 자료를 기준으로 원문 수식 복원과 짧은 객관식·계산형 문제의 신뢰성을 우선 평가하는 것입니다. 더 큰 모델 비교는 RAM 여유가 있는 환경을 확보한 뒤 별도로 진행해야 하며 이번 PC에 무조건 설치하지 않습니다.
