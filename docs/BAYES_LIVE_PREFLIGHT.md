# Bishop Bayes 실제 모델 평가 승인 전 준비

현재 상태: 실제 OpenAI API 호출 **0회**. `scripts/bayes_evaluation.py`는 기본 실행 시 계획만 출력한다. `.env`의 키 유무만 표시하고 값은 출력하지 않는다. 현재 키가 없으므로 사용자가 로컬에서 키를 설정해야 한다.

## 승인할 실행 범위

- 모델: 사용자가 선택한 `gpt-6-luna`, Responses API와 `reasoning.effort=low`. 모델을 자동 대체하지 않는다. 계정의 접근 가능 여부와 실제 작동은 미검증이며, 접근 오류 발생 시 중지한다.
- 입력: 기존 평가 사례 L01, Bishop PDF 48페이지(인쇄 28페이지), 질문, 이전 대화, 검색된 원문. 교과서 전체를 업로드하지 않는다. API 승인에는 해당 발췌와 질문의 외부 전송이 포함된다.
- 사용자 턴 3개: 정리 설명 요청 → 이해 부족 및 진단 요청 → 의도적으로 틀린 모의 학습자 답안. 도구 호출이 포함돼 HTTP 요청 수는 3회를 초과한다.
- 예상 Responses 요청 약 10–20회, 전체 최대 24회. 실제 모델의 도구 선택에 따라 상한 전에 중지할 수도 있다. 자동 재시도 없음, 요청당 출력 최대 2,400토큰, 요청당 시간 제한 45초.
- 로컬 비용 예약 한도 USD 1.00. 각 요청 전에 시스템 지침·도구 스키마·전체 문맥을 직렬화한 UTF-8 바이트 수에 8,192 여유분을 더해 입력 토큰의 보수적 대용치로 사용한다. 이 값이 80,000을 넘으면 전송하지 않는다. 출력은 추론 토큰을 포함한 최대치 전체를 예약하고 실패한 요청의 예약도 돌려주지 않는다. 캐시 쓰기 가격을 고려해 입력 예약 단가는 표준의 1.25배를 사용한다. 24회 모두 한도 크기인 경우 현재 가격 기준 예약액은 USD 0.2688이다.
- 이 제한은 로컬 추정 방식이며 OpenAI 청구 한도 자체를 설정하지 않는다. 토큰 대용치는 공식 토큰 계산기가 아니고 가격이 바뀔 수 있으므로 실제 청구액의 절대 보장은 아니다. 실제 usage와 현재 가격으로 비용 추정을 별도로 저장하고 캐시 할인을 적용하지 않는다. 예약 및 usage 누락은 기록에서 확인한다.

가격 확인일 2026-11-17: 표준 입력 USD 0.10 / 100만 토큰, 출력 USD 0.50 / 100만 토큰. 캐시 쓰기는 입력 기준 1.25배이며 기록되는 비용은 캐시 세부 정보가 반영되지 않은 추정이다. [공식 모델·가격 문서](https://developers.openai.com/api/docs/models/gpt-6-luna), [공식 도구 호출 문서](https://developers.openai.com/api/docs/guides/function-calling).

## 실행 방법

승인 없이 확인하는 계획과 오프라인 연결 검증:

```powershell
cd C:\Users\adminuser\Coding\Study
.\.venv\Scripts\python.exe scripts/bayes_evaluation.py
.\.venv\Scripts\python.exe scripts/bayes_evaluation.py --mode offline
```

실제 유료 호출은 사용자 승인 후에만 아래처럼 실행한다. 키는 사용자가 프로젝트 `.env`에 직접 설정하며 채팅에 붙여 넣지 않는다. `AI_MODE=mock`을 유지해도 이 평가 실행기는 별도 격리 경로에서 실제 모델 경로를 사용할 수 있다. 평소 앱에 키를 넣는 것만으로 평가가 실행되지는 않는다.

```dotenv
OPENAI_API_KEY=<사용자가 로컬에서 입력>
AI_PROVIDER=openai
ALLOW_EXTERNAL_AI=true
```

```powershell
# 위 범위에 대한 사용자 승인 후 실행
.\.venv\Scripts\python.exe scripts/bayes_evaluation.py --mode live --approve-paid-api
```

승인 플래그가 없으면 클라이언트 생성·데이터 복사 전에 차단한다. 일반 셸의 `OPENAI_API_KEY`는 사용하지 않는다. SDK 목적지는 공식 OpenAI URL로 고정하고 키는 SDK 인증에만 전달한다. 자동 대체 모델·유료 연결 확인·재시도를 수행하지 않는다.

## 데이터와 로그

매 실행마다 `data/bayes-evaluation-runs/<고유 ID>`에 Bishop의 문서 인덱스와 PDF만 복사한다. 기존 세션·학습 기록은 복사하거나 변경하지 않는다. 결과 `records.json`에는 턴별 요청, 모델별 호출 입력과 응답, 검색 출처, 실제 도구 로그, 시간, 사용량, 비용 추정, 출처 점검과 기존 9항목 사람 평가 양식을 저장한다. `summary.json`은 실행 단계의 확인 결과다. 각 턴 종료 후 저장하며, 호출 단위의 `model-calls.json`도 별도 갱신하므로 후속 단계 실패 시 앞선 기록이 남는다.

기록은 교과서 발췌와 퀴즈 정답을 포함하는 로컬 평가용 자료다. Git에서 제외된 `data/`에 둔다. SDK 클라이언트·인증 헤더·예외 메시지·모델 내부 추론을 기록하지 않는다. `inspect_test_storage.py`는 이 폴더도 용량만 조회하며 삭제하지 않는다. 재실행은 새 격리 폴더를 생성한다.

## 정확성 검토

자동 검증은 검색·선수 개념·문제 생성·채점·이해도 갱신·추천 도구의 성공, 문제 대기, 오답 기록, 원본 PDF 텍스트 및 페이지 일치, 인용 ID 연결을 확인한다. 실제 모델이 필수 도구를 건너뛰면 평가를 실패로 표시한다. 응답 오류, 예산 또는 입력 크기 초과 시 중지하고 이미 받은 기록은 보존한다.

사람은 Bishop PDF 48페이지의 식 (2.9)–(2.11)과 답변을 대조한다. 결합 확률의 대칭과 곱의 법칙에서 유도했는지, 원문의 X/Y와 답변의 기호 대응을 명시했는지, 분모가 양수인지, 분모가 정규화 역할을 하는지 확인한다. 생성 예제를 교과서 숫자로 표시하면 감점한다. 계산 예제는 `scripts/check_learning_math.py`의 독립 계산과 별도로 응답에 실제 사용된 수치도 재계산한다.

원문 출처가 존재한다는 사실만으로 해당 설명이 원문을 뒷받침한다고 판정하지 않는다. 선수 지식 검색 결과의 관련성, 수식 유도의 정확성, 한국어 설명과 실제 학습 효과는 사람 검토 대상이다. 실제 모델 및 사용자 실험을 수행하기 전에는 품질 점수를 채우지 않는다.
